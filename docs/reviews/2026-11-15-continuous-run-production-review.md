# Findings

## [P2] 以裁剪后的请求明细计算完整汇总会少报费用和 Token

- 文件与位置：`hub/domain/request_metadata.py::freeze_requests/thaw_requests`、`frontend/assets/views/assistant/request-metadata.js::updateGroup`。
- 所属维度：正确性、数据一致性、性能。
- 问题：终态摘要只保存最近至多 200 条、48 KiB 的明细，UI 对收到的明细相加并称作本轮汇总，省略数量未传至公共 DTO。
- 触发条件：请求明细超过数量或字节预算，随后源事件进入保留清理。
- 实际影响：本轮请求数、Token、耗时和费用变小；未保留的失败记录也不能反映在汇总状态中。
- 根本原因：完整会计统计与可裁剪明细共用唯一数据源。
- 最小修改方案：裁剪前生成完整统计并随现有摘要保存；公共 DTO 分开提供 `request_totals`、`requests` 和 `requests_omitted`，UI 只以完整统计生成汇总，并注明明细省略。旧格式仅在完整源事件仍存在时重建，否则明确为部分统计。
- 需要补充的测试：250 次请求、精确小额费用、缓存/推理拆分、保留清理、应用重启、历史 API 与旧格式缺失；真实浏览器完整值和 `≥` 标记。
- 是否阻塞合并：修复前是；已实施根因修复，须完整 CI 通过后发布。

## [P2] 分批删除事件时 API 以残存片段覆盖终态完整记录

- 文件与位置：`hub/infrastructure/platform_db_runs.py::_attach_requests`、`hub/infrastructure/platform_retention.py::_prune_run_events`。
- 所属维度：正确性、可靠性、保留生命周期。
- 问题：只要仍存在请求事件就优先读取事件；保留清理按有限批次删除，因此可读取到不完整事件集。
- 触发条件：一个终态 Run 的事件多于一次删除批次，API 在两个批次之间读取。
- 实际影响：确定性复现请求数从 4 变为 3；全部事件删完后又恢复摘要，造成历史展示前后不一致。
- 根本原因：把“存在事件”等同于“事件集完整”。
- 最小修改方案：终态有完整摘要时直接使用持久化摘要，并避免加载其历史事件。旧摘要在首次清理前补全；如果源事件此前已经部分丢失，保留更大的历史摘要并明确统计不完整，禁止以片段覆盖它。
- 需要补充的测试：每批删除一条事件，比较清理前后；旧格式在首次删除前补全；原事件不足时保留原有请求数量和部分统计标记。
- 是否阻塞合并：修复前是；已实施根因修复，须完整 CI 通过后发布。

## [P3] 过程按段数或单段正文长度裁剪时没有省略提示

- 文件与位置：`hub/domain/run_progress.py::project_progress`、`frontend/assets/views/assistant/progress.js::renderProgress`。
- 所属维度：可观测性、交互正确性、测试。
- 问题：超过 128 段时直接切片，单段正文超过 24 KiB 时也会截短；只有超过整体字节预算才设置 `truncated`，且页面没有展示已有的标记。
- 触发条件：长任务产生大量短正文和工具记录；单次或流式正文超过 24 KiB；或公共过程超过整体字节预算。
- 实际影响：用户看到早期过程消失或长正文停止更新，无法区分数据丢失与有意保留边界。
- 根本原因：段数、单段正文和整体字节边界的契约不一致，UI 未消费省略状态。
- 最小修改方案：任一边界裁剪均设置标记，页面提供真实的过程省略提示，继续复用现有 Markdown 和工具卡片。
- 需要补充的测试：150 段短正文、单次与流式长正文、整体字节边界、刷新后的标记、工具卡片与展开状态保留。
- 是否阻塞合并：非独立阻塞项；随本次修复一并交付。

## [P3] 运行时预裁剪正文未把省略状态传给公共投影

- 文件与位置：`hub/platform/runtime/native.py::NativeAssistantRuntime.run`、`hub/domain/run_progress.py::project_progress`。
- 所属维度：正确性、可观测性、测试完整性。
- 问题：运行时先按 UTF-8 字节和 JSON 转义大小裁剪 `assistant_response.text`；下游只看到已裁剪正文，无法靠再次比较文本发现上游省略。
- 触发条件：非流式长正文超过 24 KiB，或控制字符转义后超过事件正文预算；流式正文也不能依赖先前增量必然已写入。
- 实际影响：长中间回复在工具执行或后续供应商失败后被静默截短；仅直接测试投影不能覆盖该问题。
- 根本原因：裁剪发生于生产者，省略判定却只在消费者，跨层事件契约缺少标记。
- 最小修改方案：运行时发布响应事件时标明 `truncated`，公共投影只接受显式布尔真值并持久保留该标记；不扩大公开正文，不改变模型上下文或执行限制。
- 需要补充的测试：真实 worker 的 ASCII、UTF-8 与 JSON 转义三种边界，正常运行和响应检查点恢复两条路径；Run/Conversation API、事件清理后标记一致，且不重复请求模型。
- 是否阻塞合并：非独立阻塞项；6 个场景修复前全部失败，修复后专项通过，完整发布门禁仍须执行。
