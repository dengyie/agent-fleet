# Findings

## [P1] 新会话创建后路由缓存仍指向空白草稿（已修复）

* 文件与位置：`frontend/assets/app.js:86` 的 `adoptConversation`、`frontend/assets/views/assistant.js:605` 的创建回调。
* 所属维度：正确性、架构、异步状态。
* 问题：原助手直接 replaceState，但外壳的缓存 key 和当前路由仍是 `assistant:`。
* 触发条件：首次提交后点击“开始新对话”；或创建回执延迟时先进入设置，再收到回执。
* 实际影响：新对话复用已提交会话；后台回执把设置地址改成会话地址；返回可能重复挂载并丢失本地提交反馈。
* 根本原因：地址归视图写入，而缓存和导航状态归外壳维护，身份更新分散。
* 最小修改方案：创建后调用外壳回调同步 key、host、路由与导航；后台页面只更新缓存身份，不改变当前可见页面。
* 需要补充的测试：`new-chat-route`、`background-create` 在原实现失败；验证新草稿为空、设置地址不变、返回仍为原 pending 请求。
* 是否阻塞合并：修复前是；当前修复须通过完整 CI。

## [P1] 目标账号加载失败后旧表单可能写入新账号（已修复）

* 文件与位置：`frontend/assets/views/settings/catalogs.js:20` 的 `load` 与 `:130` 的保存。
* 所属维度：正确性、数据一致性、账号隔离。
* 问题：原 load 失败保留旧表单，但 currentOwner 已切换；保存读取的是可变的新目标。
* 触发条件：管理员编辑账号 A，加载 B 时 GET 503，再保存旧表单；A/B 相同配置可具有相同 digest。
* 实际影响：A 的未提交编辑可覆盖 B 同 ID 的配置，服务端 CAS 不能识别这种意图错误。
* 根本原因：表单显示内容与写入目标没有共同身份。
* 最小修改方案：每次加载先移除旧表单；渲染时固定 formOwner，默认值/目录/节点凭据使用固定账号。
* 需要补充的测试：`failed-switch` 用真实相同节点配置和目标 GET 503 验证旧保存表单消失；原实现失败。
* 是否阻塞合并：修复前是；当前修复须通过完整 CI。

## [P2] 旧保存回执会重载新编辑器并擦除未保存编辑（已修复）

* 文件与位置：`frontend/assets/views/settings/catalogs.js:36`、`:57`、`:131` 的加载序号校验。
* 所属维度：可靠性、竞态、数据流。
* 问题：原保存完成后无条件调用 load，此时 currentOwner 可能属于另一张表单；仅固定账号和序号仍无法区分同账号内已替换的编辑器。
* 触发条件：A 的 PUT 已提交但回执延迟；用户切换 B 或在同账号重新打开编辑器并输入新草稿，随后 A 回执到达。
* 实际影响：新编辑器被重新加载移除，草稿丢失；状态消息也可能对应旧操作。
* 根本原因：异步写入回执未与发起表单的生命周期关联。
* 最小修改方案：固定加载序号，保存或凭据成功后仅在原序号仍有效且原表单仍连接时显示结果/加载；旧结果不得影响新表单。
* 需要补充的测试：`inflight-save` 和 `inflight-editor` 先用真实 PUT 落库，挂起回执，分别切账号或同账号重开编辑器后释放；原实现及只加账号序号的中间版本均已复现丢失对应编辑器，最终修复保留新草稿。
* 是否阻塞合并：修复前是；当前修复须通过完整 CI。

## [P2] 在历史位置发送时新消息仍在可见区域之外（已修复）

* 文件与位置：`frontend/assets/views/assistant.js:602` 的提交渲染与滚动。
* 所属维度：正确性、交互反馈。
* 问题：自动滚动只跟随本来就在底部的页面，未区别用户主动发送。
* 触发条件：向上阅读长会话后发送一条消息。
* 实际影响：即时消息虽已创建却不可见，用户感知仍是发送后没有反馈。
* 根本原因：主动提交复用了被动内容更新的滚动策略。
* 最小修改方案：自身提交渲染后调用现有 scrollToBottom；被动更新继续尊重历史阅读位置。
* 需要补充的测试：`send-viewport` 在 1440px/390px 从历史顶部提交，挂起接受响应时即定位新消息。
* 是否阻塞合并：本轮要求下是；修复已覆盖。

## [P2] 手机模型失败自动弹出工作面板遮挡消息（已修复）

* 文件与位置：`frontend/assets/views/assistant.js:130` 的 `setStatus`。
* 所属维度：可用性、状态转换。
* 问题：failed/unknown 强制 reveal 运行详情，手机下转换为 modal。
* 触发条件：手机打开或轮询得到模型 unknown/failed。
* 实际影响：对话错误和只读“重新读取状态”入口被遮挡，用户被迫先关闭弹层。
* 根本原因：业务状态更新同时控制用户选择的详情面板可见性。
* 最小修改方案：仅选择 activity 标签，不强制打开；保留用户主动打开工作面板的路径。
* 需要补充的测试：`mobile-failure` 验证 unknown 后无 modal、可点击只读刷新、主动打开时运行标签选中。
* 是否阻塞合并：本轮要求下是；修复已覆盖。

## [P3] 程序清空多行输入后编辑框不会收缩（已修复）

* 文件与位置：`frontend/assets/views/assistant.js:154`、`:597`、`:631`。
* 所属维度：可维护性、交互反馈。
* 问题：原代码直接赋 value，不触发 ChatPromptInput 的 input 高度同步。
* 触发条件：发送多行长草稿或明确拒绝后恢复该草稿。
* 实际影响：发送后空编辑框保留大高度，压缩消息区；恢复时高度也可能不匹配。
* 根本原因：程序写入未走现有组件的同步事件。
* 最小修改方案：统一设置文本并派发 input，复用原高度计算。
* 需要补充的测试：`send-viewport` 检查发送前高度大于 100px、清空后不高于 60px、400 拒绝后恢复高度与文本。
* 是否阻塞合并：单项非阻塞；随本次修复验证。
