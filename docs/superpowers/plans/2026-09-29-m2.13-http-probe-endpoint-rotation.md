# M2.13 HTTP Probe Endpoint Rotation and Version Fencing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task with verification checkpoints. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make operator-owned HTTP probe endpoint rotation safe by binding every probe observation and Incident to the captured service version, dropping observations from superseded policies before persistence, and forcing the new policy to run independently of old evidence.

**Architecture:** The service catalog remains the source of truth and already increments `ServiceDefinition.version` on every update. The scheduler captures that version with the normalized HTTP probe policy; the IncidentService re-reads the current service immediately before writing evidence and returns a bounded `stale_policy` result when the version no longer matches. Successful and failure evidence carries the service version, due checks only consider evidence for the current version, and HTTP Incident fingerprints include the version so old endpoint failures cannot be recovered by a new endpoint.

**Tech Stack:** Python standard library, Flask application services, SQLite repositories, pytest, existing loopback HTTP fixture.

## Global Constraints

- Keep `http_probe_enabled`, `http_probe_network_enabled`, and `http_probe_sync_enabled` default-off.
- Never contact a real endpoint, VPS, Komari server, provider, or production scheduler.
- Preserve M2.11 allowlist/SSRF policy, M2.12 one-pass resolver-to-socket pinning, bounded evidence, and existing owner isolation.
- Old in-flight observations must not write evidence or Incident state after a service version changes.
- Do not expose endpoint URLs, resolver addresses, credentials, or raw response bodies in public DTOs.

## Exit Criteria

- A probe captured under service version N cannot persist after the catalog advances to N+1.
- Version N and N+1 HTTP evidence/Incidents are independently attributable and cannot cross-recover.
- A new endpoint version is due immediately even if the old endpoint produced a fresh sample.
- Existing M2.10-M2.12 behavior and all default-off gates remain green.
