# T1.8 Bounded Artifact Preview Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task with verification checkpoints.

**Goal:** Add a bounded, owner/workspace-scoped text preview for assistant artifacts while keeping binary artifacts download-only and preserving the existing integrity contract.

**Architecture:** Add a read-only JSON preview endpoint that reuses `ArtifactStore.read()` for full SHA-256 verification, allows only a fixed text MIME allowlist, and returns at most 64 KiB of UTF-8 text plus truncation metadata. Extend the existing platform API boundary and assistant DOM renderer with an explicit preview toggle; preview text is inserted into `<pre>` text nodes and is never interpreted as markup.

**Tech Stack:** Flask platform routes, Python `ArtifactStore`, vanilla ES modules, DOM-safe rendering, pytest source/route contracts, Playwright loopback walkthrough.

## Global Constraints

- Preserve the protected primary worktree and all existing user changes.
- Keep `platform_enabled`, provider, Node, VPS, Komari, scheduler, and mutation gates unchanged and default-off.
- Preview is owner-scoped, workspace-scoped, integrity-checked, and bounded to `64 * 1024` UTF-8 bytes.
- Only `text/plain`, `text/markdown`, `text/csv`, and `application/json` are previewable; all other content types remain download-only.
- The frontend API client is the only HTTP boundary; views must not call `fetch` or use `innerHTML`.
- Dynamic preview text must be written with `textContent`; no HTML, iframe, object URL, or executable content path is introduced.
- A preview failure must not remove the artifact row or change the existing download behavior.
- Obsidian notes must be updated through the canonical agent-fleet project entry and router/MOC mounts.
