# M2.7 Budget Telemetry and Rate Limits Implementation Plan

> **For agentic workers:** Execute this plan task-by-task with focused tests after each task.

**Goal:** Persist provider usage for every assistant Run and add an opt-in owner/model sliding-window budget admission boundary that fails closed before provider requests.

**Architecture:** The platform SQLite database gains a bounded usage ledger owned by `UsageRepository`. A runtime usage meter reserves one request before `ModelProvider.complete`, settles the reservation exactly once with normalized provider usage, and records an unknown request when the provider boundary raises after dispatch. Run terminal state carries a compact usage summary, while the ledger remains the source of detailed request accounting. No policy row means limits are disabled; no network, VPS, service manager, or background scheduler is introduced.

**Tech Stack:** Python standard library (`sqlite3`, `time`, dataclasses, typing), existing provider `ModelResponse.usage`, Flask bootstrap dependency injection, pytest.

## Global Constraints

- Usage limits are disabled unless an explicit owner/model policy is stored; existing defaults and rollout gates remain unchanged.
- Admission occurs before `ModelProvider.complete`; a rejected request never calls provider transport.
- Every admitted provider boundary settles exactly once by a unique `(run_id, attempt, step)` key; retries or duplicate callbacks cannot double count.
- Provider failures after admission release no reservation only after an `unknown` usage event is recorded, so request accounting remains conservative.
- Usage rows contain counts and bounded identifiers only; no prompts, completions, secrets, endpoints, or raw provider payloads are persisted.
- Sliding-window checks use an injected clock and SQLite transaction; expired reservations are reclaimed before evaluating a limit.
- Existing platform gates remain default-off and the full repository regression must stay green.

**Interfaces:**
- `UsageRepository(db_path).init()` creates `platform_usage_limits`, `platform_usage_reservations`, `platform_usage_events`, and `platform_run_usage`.
- `UsageRepository.set_limit(owner_id, model_key, request_limit, token_limit, window_s, enabled=True)` returns a redacted policy DTO.
- `UsageRepository.admit(owner_id, model_key, run_id, attempt, step, now)` returns `UsageReservation | None`; it raises `UsageLimitExceeded` before provider invocation when the policy would be exceeded.
- `UsageRepository.settle(reservation, usage, outcome)` is idempotent; `outcome` is `succeeded`, `failed`, or `unknown`; unknown counts one request even when usage is absent.
- `UsageRepository.get_run_usage(owner_id, run_id)` returns `{input_tokens, output_tokens, total_tokens, provider_requests}`.

    repo.set_limit("owner@example.test", "model-a", request_limit=1, token_limit=10, window_s=60)
