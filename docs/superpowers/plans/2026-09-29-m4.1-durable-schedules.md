# M4.1 Durable Read-only Schedules Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add a default-off, owner-scoped durable schedule control plane for bounded read-only service health and HTTP probe checks.

**Architecture:** Keep schedule definitions and trigger leases in the platform SQLite database beside existing platform repositories. A small service validates fixed action types, computes bounded interval occurrences, applies one bounded missed-run catch-up and overlap policies, and invokes an injected deterministic read-only executor. Trigger identity is (schedule_id, scheduled_at) so retries and Hub restarts are idempotent. No provider, node, VPS write operation, or notification is called.

**Tech Stack:** Python 3, SQLite/WAL, Flask operator routes, pytest.

## Global Constraints

- All new automation remains disabled unless platform_schedules_enabled and platform_enabled are both true.
- Supported actions are fixed read-only identifiers: service_health and http_probe.
- Intervals are bounded to 5 seconds through 24 hours; public payloads never expose lease tokens or raw executor output.
- Missed-run handling is skip or one bounded catch_up; overlap handling is skip or coalesce.
- Every schedule and trigger query is owner-scoped and every trigger is unique on (schedule_id, scheduled_at).
