# M4.2 Owner-scoped Memory Items Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a default-off, owner-scoped MemoryItem store with bounded CRUD and safe SQLite FTS search for the main assistant.

**Architecture:** Memory items live in additive SQLite tables beside the platform store. A repository owns validation, optimistic revisions, FTS indexing, and owner filtering; an application service translates storage failures into stable application errors; a gated Flask adapter exposes bounded operator CRUD/search. Memory remains explicit user data: no automatic model extraction, no prompt injection into Runs, and no cross-owner access.

**Tech Stack:** Python 3, SQLite FTS5, Flask, pytest.

## Global Constraints

- `platform_memory_enabled` is false unless both `platform_enabled` and the memory gate are true.
- Memory kinds are fixed to `fact`, `preference`, `decision`, and `note`.
- Title, content, tags, source, list/search limits, and query terms are bounded before persistence or FTS.
- Every repository method requires an owner and every public DTO omits `owner_id`, raw FTS rank, and internal SQL fields.
- Updating or deleting requires the current revision; duplicate client tokens are not accepted as memory identifiers.
- This slice does not call a model, ingest conversation text automatically, send notifications, or execute VPS/node actions.
