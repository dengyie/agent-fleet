# M2.6 Platform Backup and Restore Implementation Plan

> **For agentic workers:** Execute this plan task-by-task with focused tests after each task.

**Goal:** Add an offline, integrity-checked backup and restore contract for the platform SQLite database and content-addressed artifact store before any production gate is enabled.

**Architecture:** `PlatformBackupService` uses SQLite's online backup API so WAL state is captured consistently, inventories every artifact manifest/content pair with bounded SHA-256 metadata, and writes a versioned backup envelope atomically. Restore validates the envelope, database integrity, artifact paths, sizes, and hashes before staging a complete pair under a new root; it never overwrites an existing destination. No Flask route, scheduler, network connector, secret resolution, or production deployment is added.

**Tech Stack:** Python standard library (`sqlite3`, `hashlib`, `json`, `shutil`, `tempfile`, `pathlib`), existing `PlatformRepository`/`ArtifactStore`, pytest.

## Global Constraints

- Backup and restore are local filesystem operations only; no endpoint, provider, VPS, Komari network, or background worker is used.
- SQLite is copied with `Connection.backup`, not a raw file copy, so a live WAL database is restorable.
- Artifact symlinks, missing manifests, malformed metadata, path traversal, size mismatches, hash mismatches, and SQLite integrity failures fail closed with bounded error codes.
- Restore stages and validates the complete database/artifact pair before publishing one new destination directory; existing destinations are never overwritten.
- The backup envelope contains only schema/version, bounded file inventory, sizes, and hashes. It never contains secret values, raw artifact content, or absolute source paths.
- Existing platform gates remain unchanged and default-off.
