# M2.2 Disposable Node Runtime Fixture Implementation Plan

> **For agentic workers:** Execute this plan task-by-task with focused tests after each task.

**Goal:** Wire the M2.1 fixed service-log reader into an explicit, capability-scoped local Node runtime and prove the complete Hub poll -> Node subprocess -> receipt -> post-check path against a disposable host fixture.

**Architecture:** Add a small `NodeRuntime` assembly boundary that requires an explicit runtime configuration, constructs the existing `DirectoryBackend`, `NodeToolExecutor`, `FixedServiceLogReader`, `NodeJournal`, and `NodeClient`, and exposes only the capabilities declared by the fixture. The reader continues to own all service argv; the fixture supplies temporary executable shims through `PATH` so tests exercise real `subprocess.run` without contacting a host service. No production bootstrap, VPS connector, or default gate is enabled by this slice.

**Tech Stack:** Python standard library, existing `NodeClient`/`NodeJournal`/`NodeToolExecutor`, Flask test client transport, pytest, temporary directories and executable shims.

## Global Constraints

- Runtime construction requires an explicit node id, credential, journal path, and workspace root.
- Service log execution is unavailable unless `reconcile.service.logs` is explicitly declared in the runtime capability set.
- The runtime never accepts caller-supplied executable, argv, unit, path, or shell fragments for service logs.
- Fixture subprocesses use `shell=False`, a temporary PATH prefix, bounded timeout, and bounded UTF-8 output.
- Tests must use only temporary local files and loopback/in-process transport; no production endpoint, credential, VPS, or provider is contacted.
- Existing direct `NodeClient` and `NodeToolExecutor` callers remain backward compatible.

## Exit Criteria

- A configured local Node runtime can execute a fixed service-log post-check through the real subprocess runner against a temporary fixture executable.
- Removing the explicit capability prevents any log subprocess from running.
- Duplicate command delivery is journal-idempotent.
- Public receipts contain only bounded, redacted evidence; no credential or host path escapes.
- No production network, VPS, service manager, provider endpoint, or default gate is enabled.
