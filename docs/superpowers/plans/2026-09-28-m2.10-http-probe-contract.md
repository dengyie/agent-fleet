# M2.10 Versioned HTTP Probe Contract Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task with verification checkpoints.

**Goal:** Add a versioned, bounded, read-only HTTP probe evidence source that can be validated against a disposable loopback fixture before any production endpoint or scheduler wiring is considered.

**Architecture:** Add an isolated `HttpProbeClient` with an explicit default-off network gate and an adapter-owned urllib GET path. `HttpProbePayloadContract(schema_version=1)` validates only a small health envelope and drops unknown fields before creating an immutable snapshot. A deterministic evidence normalizer maps the snapshot into the existing `ServiceHealthService` contract; bootstrap and background monitoring remain unchanged until a later rollout decision.

**Tech Stack:** Python standard library `urllib`, dataclasses, JSON, temporary `ThreadingHTTPServer`, existing Flask service-health store, pytest.

## Global Constraints

- `allow_network=False` remains the default and must fail before opening a socket when no requester is injected.
- The canary may contact only a test-owned `127.0.0.1` loopback server on an ephemeral port.
- The client sends one read-only `GET` to the exact configured path, with `Accept: application/json` and no credentials or query injection.
- Response bodies are bounded before JSON decoding; raw body, headers, endpoint details, and sentinel fields never enter snapshots, evidence, or error strings.
- `schema_version: 1` is the only version accepted by the contract; unsupported or malformed envelopes fail closed with stable error codes.
- The source is additive and unconnected to Flask routes, background jobs, service actions, Komari sync, provider access, or production configuration.
