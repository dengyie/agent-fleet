# T3.6 Browser Node Data-plane Contract

> Status: implemented as a default-off contract slice in local `main` (`3a76ce2`). This record does not claim a production browser integration or deployment.

## Scope

T3.6 extends the existing agent-fleet Hub/Node command plane with a bounded browser capability. The Hub remains the control plane for Runs, commands, leases, policy admission, artifact tickets, and durable session metadata. The Node remains the execution data plane and uses the existing outbound poll, receipt, and push transport.

This slice does not add Hermes, a browser sidecar, reverse SSH, a central private key, a second command transport, or a production browser service. It does not implement real Chromium/Playwright, Browserbase, SecretBroker, `browser.frame`, assistant observation UI, Take Control/Return Control, interactive writer grants, or `browser.submit`.

## Contract

- `platform_browser_enabled`, `platform_browser_network_enabled`, and browser origin configuration are default-off and platform-gated.
- User-supplied loopback HTTP(S) URLs are rejected by Hub and Node policy. Disposable loopback URLs are permitted only through the explicit test fixture override injected into the T3.7 transport; the override is unavailable through Hub, Node manifests, user input, and production config. External navigation requires the browser and network gates, an exact configured origin, no embedded username/password, and global IP/DNS answers. The T3.7 redirect and DNS-to-sockaddr contract is covered at its offline transport seam; that transport is not wired to a real browser driver and does not establish browser-process egress enforcement.
- `browser.session` is the required Node capability. An enabled Node declaring it receives the fixed browser tool set: `open`, `navigate`, `snapshot`, `screenshot`, `click`, `type`, `scroll`, `back`, and `close`.
- The Hub checks the selected owner-scoped Node catalog entry before exposing browser tools or admitting a browser command. The Node repeats capability, argument, URL, and backend validation. Browser commands never fall back to the Hub workspace executor.
- Arbitrary JavaScript, CDP evaluation, shell, raw command, host PID, profile upload, cookies, credentials, and secrets are not supported.
- Deterministic policy and backend errors are `failed`. An exception after dispatch with an indeterminate side-effect outcome is `unknown`; browser commands use `manual_only` retry semantics and are not automatically replayed.
- Screenshot receipts require the PNG magic bytes and are limited to `256 KiB`. Raw bytes are uploaded through a one-time artifact ticket and are replaced by bounded artifact metadata before Node journal, Hub receipt, Run event, or model serialization.
- Artifact tickets store only a token digest. Upload requires the node credential, separate upload token, command/idempotency headers, and worker identity. Unconsumed uploads require the current leased screenshot command and active worker lease; consumed-ticket replay validates the command and ticket scope but may retrieve the already-published artifact after command completion. Owner/workspace/run/node/command scope, expiry, maximum size, hash, idempotency, reset, concurrency, and replay behavior are enforced.
- Durable browser sessions contain only opaque session id, owner/workspace/run/node/profile/backend/state/timestamps. `browser.open` registers a session only after the Node backend succeeds; `browser.close` is terminal-idempotent. Hub derives scope from the leased command, and Node shutdown can close local injected sessions through `NodeRuntime.close_all()`. The Node binds each local session to the signed command `run_id`, rejecting cross-run reuse. If Hub registration fails after open, the Node closes and removes that local driver session while retaining the command's `unknown` outcome.
- Browser backend results enforce aggregate UTF-8/byte and element-count budgets in addition to per-leaf, depth, and container limits. Malformed URL parser failures map to deterministic `invalid_url` policy errors.

## Deferred Boundaries

M1.7 and T3.4 remain accurate that real PTY/browser attachment is not implemented. This T3.6 slice is a contract-level, default-off addition using an injected driver interface and in-process HTTP tests. It must not be described as production-ready browser automation.

Deferred work includes real Chromium/Playwright lifecycle and wiring the T3.7 transport into a browser-native request interceptor plus process-level egress enforcement, Browserbase, SecretBroker-backed browser credentials, assistant observation surfaces, product-approved observation policy, real-driver Take Control/Return Control races, Node crash reconciliation/expiry cleanup beyond the current durable close contract, and T3.8-T3.9. Screenshot/frame artifacts, execution-window writer fencing, and approval-gated `browser.submit` were implemented by later approved slices, but remain injected-driver contracts rather than real-browser acceptance. Production gates remain closed and no deployment is authorized by this record.
