# T1.5 Assistant Artifact Interaction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task with verification checkpoints.

**Goal:** Make workspace artifacts produced by an assistant Run visible in the `/assistant` workspace with owner-scoped metadata and safe same-origin download links.

**Architecture:** Keep `frontend/api/platform.js` as the only platform HTTP boundary. Add a bounded JSON manifest list wrapper and a URL builder for the existing integrity-checking content route; the view never calls `fetch` or concatenates untrusted markup. The assistant binds artifacts to the conversation's persisted `workspace_id`, renders bounded DOM nodes with `textContent`, and refreshes after conversation recovery and Run completion. Download remains available through the integrity-checked `Content-Disposition: attachment` route; the separately bounded T1.8 preview is opt-in and text-only.

**Tech Stack:** Flask platform artifact API, vanilla ES modules, DOM-safe rendering, Python `unittest`/`pytest` source-contract tests.

**Execution status (2026-09-29):** Implemented in the isolated `codex/agent-fleet-platform-m1` worktree. The completed slice includes bounded manifest/download helpers, conversation-scoped assistant rendering, worker artifact workspace fencing, filename/header hardening, and route/worker/frontend regression coverage. The follow-up T1.8 slice now adds a separate bounded text preview route and DOM-safe preview toggle; the original download contract remains unchanged.

The T1.8 follow-up is tracked in `docs/superpowers/plans/2026-09-29-t1.8-artifact-preview.md`. It permits only four text MIME types, verifies the complete artifact before truncating to `64 KiB`, keeps binary rows download-only, and renders preview data through a `<pre>` text node. Focused artifact/sandbox/route/frontend verification is `16 passed`; a loopback Chromium walkthrough confirmed literal markup rendering, truncation, binary download-only behavior, and workspace isolation.

## Global Constraints

- Preserve all existing uncommitted changes and do not edit the protected primary worktree.
- Platform gates remain default-off; do not contact real VPS, providers, Komari endpoints, or production services.
- All artifact responses remain owner/workspace scoped and expose only public manifests.
- The frontend API client is the only HTTP boundary; views must not call `fetch` or use `innerHTML`.
- Dynamic artifact names and metadata must be written with `textContent`; download URLs must be built from encoded path segments and an encoded workspace query.
- Obsidian notes must follow the obsidian-doc-router anti-orphan SOP and be mounted in the canonical router and project MOC.

### Task 2: Add the bounded platform artifact API helpers

**Files:**
- Modify: `frontend/api/platform.js`

**Interfaces:**
- `getPlatformArtifacts(workspaceId, limit)` calls `platformRequest(apiPath('platform','v1','workspaces', workspaceId, 'artifacts') + '?limit=...')` after clamping finite numeric limits, and validates the response as an object.
- `getPlatformArtifactContentUrl(artifactId, workspaceId)` calls no network API; it returns `apiPath('platform','v1','artifacts', artifactId, 'content') + '?workspace_id=' + encodeURIComponent(workspaceId)`. Empty/non-string identifiers return a URL only after `apiPath` applies its existing segment encoding rules.
