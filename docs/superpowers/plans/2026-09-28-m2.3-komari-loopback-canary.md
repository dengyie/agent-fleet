# M2.3 Komari Loopback Read-only Canary Implementation Plan

> **For agentic workers:** Execute this plan task-by-task with focused tests after each task.

**Goal:** Validate the Komari read-only integration over the real standard-library urllib path against a disposable loopback HTTP fixture while keeping production network access explicitly disabled by default.

**Architecture:** Extend KomariClient with an explicit allow_network gate and an adapter-owned urllib requester. The requester sends only the configured read-only node path and a bearer credential, bounds status/body/timeout handling, and maps all transport failures to stable KomariError codes. Existing injected requesters remain the default testing seam. A loopback ThreadingHTTPServer fixture proves request shape, normalization, token isolation, oversized response rejection, and the monitoring sync path without contacting an external host.

**Tech Stack:** Python standard library urllib.request, ThreadingHTTPServer, Flask test client, existing KomariClient/PlatformMonitoringService, pytest.

## Global Constraints

- allow_network=False remains the default and must fail closed before opening a socket.
- The canary may contact only a test-owned 127.0.0.1 loopback server on an ephemeral port.
- The client sends a GET request to the exact configured path with Authorization: Bearer <token> and no query/fragment injection.
- Response body is bounded before JSON decoding; token, raw body, and response headers never enter public snapshots or error strings.
- Komari remains read-only: no POST, mutation, background thread, or production endpoint is added.
- Existing injected requesters and all default-off gates remain backward compatible.

## Exit Criteria

- Real urllib GET path is verified against a temporary loopback server.
- Network-disabled configuration opens no socket.
- HTTP, timeout, oversized body, and invalid response outcomes have stable bounded error classes.
- Monitoring sync consumes normalized snapshots without exposing the token or raw response.
- No production Komari endpoint, VPS, credential, or background network operation is used.
