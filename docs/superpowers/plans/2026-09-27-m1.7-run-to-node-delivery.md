# M1.7 Run-to-Node Delivery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox ([ ]) syntax for tracking.

**Goal:** Route a Run tool call to a selected execution Node through the existing durable signed command/outbox protocol, wait for a durable receipt, and surface an ambiguous or lost receipt as unknown without replaying the side effect.

**Architecture:** Keep the current local ToolBroker path unchanged when a Run has no remote execution node. Add a RemoteToolBroker adapter that converts an allowlisted tool call into one PlatformCommand, waits through the Hub command repository for a terminal receipt, and returns a bounded ToolReceipt. The worker selects the adapter from the immutable Run snapshot and a default-off remote execution gate. NativeAssistantRuntime maps an unknown remote receipt to an unknown Run so later reconciliation can inspect it.

**Tech Stack:** Python 3.13, Flask, SQLite/WAL, existing PlatformCommand, CommandRepository, CommandDeliveryService, NodeClient, and pytest. No new dependency and no real Node/VPS call.

## Global Constraints

- platform_remote_execution_enabled is false by default and is forced off when platform_enabled is false.
- Remote commands use fixed tool names and adapter-owned tool.<name> actions; model-authored shell, SSH, PTY, browser, and arbitrary argv remain unavailable.
- Command arguments are bounded by the existing command envelope; Run events contain only command id, node id, tool, and status metadata, never raw arguments, secrets, or receipt result bodies.
- A missing, expired, or unknown receipt is never retried automatically.
- Real network, real VPS, real restart, and real PTY/browser attachment remain out of scope.

- The plan covers durable command lookup, remote adapter selection, Run state mapping, Node fixed-tool execution, tests, docs, and verification.
- No task enables production network or executes a real VPS operation.
- Every remote side effect has one command id and an explicit unknown outcome; no blind replay is introduced.
- Reconciliation evidence is an audit record, not a client-controlled status transition; the first deterministic workspace post-check is tracked in `docs/superpowers/plans/2026-09-27-m1.9-deterministic-postcheck.md`.
