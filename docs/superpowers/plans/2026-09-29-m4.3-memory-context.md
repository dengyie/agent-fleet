# M4.3 Memory Context Selection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Let an operator explicitly select owner-scoped MemoryItems for a turn, freeze the selected content into the Run snapshot, enforce item/byte budgets, and expose bounded evidence without automatic memory injection.

**Architecture:** Add a separate default-off context gate beneath the existing platform and MemoryItem gates. PlatformMemoryContextService resolves either explicit IDs or an explicit FTS query at turn creation, validates optional revisions, renders a bounded frozen item list, and stores it in config_snapshot; the worker prepends a bounded reference-only system message from that snapshot and journals only counts, IDs, mode, and budgets. Existing owner scope, Run lease fencing, and provider boundaries remain authoritative.

**Tech Stack:** Python 3, Flask, SQLite/FTS5, existing platform repositories/services, pytest.

## Global Constraints

- platform_memory_context_enabled is false by default and is effective only when platform_enabled and platform_memory_enabled are true.
- A turn must opt in with memory_context.enabled=true; no conversation text, model output, or background process may create a selection.
- A selection uses exactly one of memory_ids or query; IDs and query results are owner-scoped and frozen before the Run is committed.
- max_items is bounded to 1..20 and max_bytes to 256..32768; the rendered context must never exceed max_bytes UTF-8 bytes.
- Frozen items include only bounded public MemoryItem fields and revision; provider input is rebuilt from the Run snapshot, never reread from live memory rows.
- Run events contain bounded metadata and never full memory title/content/tags.
- Existing gates stay default-off, ordinary platform startup must not initialize memory context storage, and existing tests/contracts must remain green.
