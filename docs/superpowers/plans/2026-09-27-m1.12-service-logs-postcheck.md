# M1.12 Service Logs Deterministic Post-check Implementation Plan

**Goal:** Add an owner-scoped, read-only reconciliation path for ambiguous `service.read_logs` commands. The path records current bounded log evidence without claiming that the evidence was caused by the original command.

**Architecture:** The Hub validates the original unknown command, reloads the current ServiceDefinition, and fences node, service id, adapter, target alias, and service version. It derives a deterministic `reconcile.service.logs` command containing only the adapter-owned log envelope: service version, bounded window, and bounded byte limit. The Node accepts that exact envelope and calls an injected fixed log reader. The reader output is redacted with the existing Redactor and truncated to a strict byte bound before the receipt is persisted. A successful read records `matched` current evidence; failed, interrupted, stale-version, or unknown reads record `remains_unknown`. The original command and Run remain `unknown`.

**Tech Stack:** Existing Flask platform routes, SQLite command repository, `CommandPostcheckService`, `NodeToolExecutor`, `NodeClient`, `DiagnosticService`, `tools.session.redact.Redactor`, pytest.

**Global Constraints:** No arbitrary executable, argv, path, journalctl unit, or client-supplied service identity. No service mutation. No raw unredacted logs, credentials, leases, or full command arguments in public DTOs/events. Production remote execution and monitoring gates remain unchanged and default-off.

## Exit Criteria

- Only the exact adapter-owned logs envelope can be executed.
- A successful current read is bounded and redacted, and is explicitly current evidence rather than causal proof.
- Original command and Run remain `unknown` in every post-check outcome.
- All gates and production integrations remain unchanged.
