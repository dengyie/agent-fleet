# Shared Linux test node registration implementation plan

**Goal:** Allow explicitly registered workspaces of one owner to share the same fixed-test node without multiplying its capacity or replacing workspace-scoped inputs and conversations.

**Architecture:** Reuse the existing `NodePolicy.workspaces` and original global node reservation ledger. In the operator manifest loader, merge only the workspace set of otherwise identical node policies. Retain separate RegisteredRunTarget, RegisteredNodeInputs and selection requirements for every workspace. Conflicting node-wide policies fail before composition publishes registrations. No schema, wire protocol, Node runtime, slot count or execution lifecycle changes.

**Cross-platform download fix:** The actual signed-source receive regression exposed a POSIX-only Hub capacity entry. Reuse the existing Windows pinned directory handles and kernel slot locks, creating a private `.artifact-capacity` child relative to the pinned database parent. Do not rewrite application ACLs or relax the existing artifact-root contract. The Windows Node test uses the existing native probe's private input/journal directories. Verify reopened handles, global/node limits, process races, process death and an unsafe existing child. Windows Hub chunked-upload service remains POSIX-only and is not claimed by this download fix; its original failures are preserved separately. Linux remains the deployment target for the complete upload/download chain.

**Constraints:** Python3.10; UTF-8 without BOM; isolated feature worktree; primary main remains protected. No downloads, production writes, deployment or automatic acceptance. Same-node residency conflicts remain explicit errors; architecture/software remain workspace-specific filters against the actual report.
