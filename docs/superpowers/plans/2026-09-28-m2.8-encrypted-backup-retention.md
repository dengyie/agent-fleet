# M2.8 Encrypted Backup Retention and Restore Contract Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task with verification checkpoints.

**Goal:** Extend the local platform backup contract with streamed AES-256-GCM encryption, key-identity fencing, bounded retention planning, and a disposable restore drill so the platform can prove an encrypted backup/restore window before any production rollout.

**Architecture:** Keep `PlatformBackupService` as the source of truth for validating the SQLite/artifact pair. Build an encrypted directory beside it: each validated backup file is encrypted independently with streaming AES-GCM, a public manifest contains only bounded paths, sizes, hashes, ciphertext metadata, and a non-secret key id, and restore decrypts into a fresh sibling before re-running the existing full validation. A separate retention planner returns a dry-run deletion plan and only deletes complete encrypted backup directories when explicitly requested; it never follows symlinks or deletes arbitrary children.

**Tech Stack:** Python standard library (`hashlib`, `json`, `os`, `pathlib`, `tempfile`), `cryptography` AES-GCM streaming primitives, existing SQLite/artifact backup service, pytest.

## Global Constraints

- Existing unencrypted `create_backup`, `inspect_backup`, and `restore_backup` interfaces remain backward compatible.
- Encryption uses `cryptography` AES-256-GCM; no hand-written cryptography and no key material in manifests, errors, logs, or docs.
- Plaintext backup data exists only in a private temporary directory during encryption/decryption and is removed on every success and failure path.
- A target is published only with an atomic no-overwrite rename after structural and content validation.
- Encrypted restore never extracts a manifest-controlled path outside its fresh staging directory and never overwrites an existing destination.
- Retention defaults to dry-run; deletion requires an explicit `apply=True`, a bounded policy, and an encrypted-backup marker.
- No Flask route, scheduler, provider endpoint, Komari endpoint, VPS, production credential, or deployment gate is enabled by this slice.
